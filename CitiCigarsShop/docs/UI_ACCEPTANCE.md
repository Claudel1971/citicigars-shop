# UI Acceptance

## R0

Aucune nouvelle UI fonctionnelle n’a été construite pendant R0. Aucune acceptation visuelle n’est revendiquée.

## Owner Visual Acceptance — obligatoire

Chaque jalon UI doit être évalué séparément sur :

- compréhension immédiate ;
- vitesse d’exécution ;
- français métier ;
- mobile ;
- visibilité des preuves/fraîcheur ;
- confirmations et erreurs ;
- absence de codes internes par défaut ;
- drill-down ;
- accessibilité ;
- cohérence des actions.

## Parcours proposé pour R1

1. Ouvrir “Aujourd’hui”.
2. Comprendre trois changements importants.
3. Ouvrir une exception stock sans mutation.
4. Drill-down jusqu’au lot/mouvement.
5. Ouvrir un client/fournisseur lié.
6. Voir l’action proposée, la preuve et le risque.
7. Revenir au contexte initial sans perte.

## Gate

R1 ne peut être accepté uniquement par tests. Claudel doit donner un Owner Visual Acceptance explicite.
